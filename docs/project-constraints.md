# DshForMac 项目约束

通用产品与技术约束见 [AGENTS.md](../AGENTS.md)，具体流程见 [架构设计](architecture.md)。

## 子进程环境

- 子进程 PATH 优先使用选定 Node 与检测到的 pnpm 目录，保留继承路径，读取 `/etc/paths` 和 `/etc/paths.d`，再补齐两种 Mac 架构的 Homebrew 与系统目录，支持 DSH 内交互式 shell 查找配置依赖。仅影响子进程，不修改全局 PATH 或用户 shell 配置。
- 内嵌终端可使用本机已安装的 Nerd Font 补充私用区图标；兼容样式仅作用于终端，不自动安装字体、不修改 DSH 包。
- DSH 0.2.0-rc.2 的主对话根节点通过插槽属性定向补充 flex 高度适配，避免 WebKit 的百分比高度解析使消息区塌缩、输入框贴到顶部；不修改受管 DSH 包。
- 回退至早于 DSH 0.2.1-alpha.1 的版本时，按需适配浏览器草稿格式。新版结构化草稿只向旧页面提供字符串投影；读取不改写原记录，写入保留未修改的引用和其他字段，不清空浏览器存储、会话或配置。新版 DSH 不注入此适配。

## DSH 文件界面

- 兼容旧版 macOS（最低 macOS 11）是核心要求。DSH 已内置某项功能，不代表旧版系统 WebKit 已具备其依赖的 API；移除原生重复功能时，须保留必要的 WebKit 兼容层。
- 文件与产出物（含 PDF）预览由 DSH 内置功能处理，不保留原生预览栏、渲染器或文件打开 RPC 拦截。会话与 PDF 所需的 API/Worker 兼容补丁继续保留，只在系统缺少对应 API 时补齐，不修改受管 DSH 包。
- 兼容补丁须依据精确版本的浏览器发布代码调用审计，区分原生 API、库方法和上游已提供的回退。补丁保持原生实现，页面与 PDF Worker 共用安装器；structuredClone 不通过 JSON 丢失数据，ArrayBuffer 转移须实际脱离源缓冲区。不能完整模拟的宿主对象明确拒绝，不伪造图形或垃圾回收能力。当前审计范围和实测边界见 [WebKit 兼容审计](webkit-compatibility.md)。
- PDF Worker 构造兼容不得改变原生 Blob 的 prototype 或破坏 File、slice、Response.blob/formData 返回对象的 `instanceof Blob` 语义，须覆盖 DSH multipart 二进制响应的类型校验与字节保真回归测试。
- DSH Market 重启功能使用独立桥接，仅处理同源 `POST /dsh-market/restart`；原生层校验本机主框架与私有令牌，不读取文件打开请求正文。

## 菜单栏控制

- 菜单栏顶部显示 DshForMac 版本和 DSH 当前状态，操作区提供显示主窗口（⌘0）、重新加载页面（⌘R）、重启 DSH（⇧⌘R）和应用设置（⇧⌘,）；⌘, 留给 DSH 内嵌页面的设置。其后集中放置 DSH 与应用更新检查，退出单独成组。关闭窗口不停止 DSH。
- 主窗口记住上次尺寸和位置；外接显示器变化后，不能让窗口停留在不可见区域。
- 唤醒后只探测已运行的本机 DSH 服务；确认断线后有限重试并在恢复后重载页面，失败时提供手动重连。不因探测自动下载或重启 DSH。

## DshForMac 应用更新

- 应用包标识为 `cn.hpyer.dshformac`；首次启动时从旧包标识的偏好设置域迁移用户设置，不清除旧域。
- 应用版本更新与 DSH 运行时更新互不依赖；即使 Node.js 或 DSH 不可用，也能检查 DshForMac 更新。
- 仅发布同时包含 x86_64 与 arm64 的单个通用 DMG，继续支持 macOS 11。更新包和更新源使用 Sparkle EdDSA 签名；不要求 Apple Developer ID 签名或公证。
- 默认每天检查应用更新，不静默下载或安装。发现新版后由用户选择稍后提醒、忽略此版本或立即升级；立即升级应安装并重启应用。
- 设置中的应用版本号旁与菜单栏均提供手动检查入口。检查、下载或安装失败时显示原因，并提供重试及 GitHub Releases 手动安装入口；签名校验失败不得绕过校验自动安装。
- 应用更新源是 GitHub Release 中的固定 `releases/latest/download/appcast.xml` 地址，不使用 GitHub Releases API。发布工作流缺少 Sparkle 私钥时不得发布不受验证的更新。
- 源码运行、只读 DMG 或应用转置环境不执行应用内替换；引导用户从发布页面手动安装。现有未包含更新器的旧版本需要手动升级一次。

## DSH 更新

- DshForMac 当前最低兼容 DSH 版本由 `AppMetadata.minimumSupportedDSHVersion` 统一记录，为 `0.1.6` 正式版。按 SemVer 比较，`0.1.6` 的预发布版本不满足门槛，后续更高版本的预发布版本可用。低于该版本的受管运行时不得启动、下载或作为回退目标；版本检查失败时不删除目录或改写用户选择，并在启动时提示检查 DSH 更新。设置中不重复显示此门槛；后续成功启动仍遵循正常的受管版本保留规则。
- 提高门槛是为避开旧会话格式读取器：上游 [V3 → V4 会话格式变更](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/persistence-changes/2026-09-16-session-format-v4.md) 明确旧 V3 读取器拒绝新版会话。最低版本门槛不保证任意版本间的数据回退兼容；常规会话迁移由 DSH 负责。macOS 最低版本继续保持 11。
- 降级导致的未知必需事件错误可由用户主动触发兼容修复；不得自动修改日志或笼统忽略未知事件。目标版本不按发布号设白名单；须满足应用最低版本要求，并提供 V4 严格读取器和可用的会话锁。仅将完整 V4 日志中目标版本不认识的 `job/registered`、`job/settled` 标记为可忽略，保留消息、事件载荷与序号，明确说明旧版不能恢复新版后台任务状态。相同 V4 格式号不代表相同事件集合；目标版本已经认识的事件不改写，其他必需未知事件、格式或缺失的读取能力必须拒绝。
- 修复须先备份原始压缩日志并校验 SHA-256，再生成临时文件，使用目标受管版本的严格读取器验证后原子替换。备份持久保存在应用数据目录 `session-backups/`，不自动清理；备份或校验失败不得替换。停止本应用管理的 DSH 并取得上游 `session.lock` 的排他锁后才能写入，不强行占用其他进程的会话。修复与恢复都检查日志摘要，拒绝覆盖检查后的新增历史；恢复前也备份当前日志。只处理默认 `~/.dsh/sessions/` 内的规范路径，不跟随符号链接，不输出会话正文或第三方原始异常。
- 每个新应用版本的 `CHANGELOG.md` 条目都必须记录该最低 DSH 版本；发布工作流校验它与应用常量一致，随后原样生成 GitHub Release Notes。日常开发不修改更新日志。
- 设置中的“DSH 检查标签”支持多选，首项 `latest` 默认勾选且不可取消；检查标签与包下载镜像修改后立即保存，后续检查和下载直接使用新设置，无需先点击“保存”。
- 设置页的 DSH 检查入口和结果位于“运行状态”栏，提供独立的“关闭”按钮；保存普通变更后保持窗口打开，用户确认立即重启 DSH 时才自动关闭。
- 检查频率支持每次启动、每天、每周、每月和不检查。周期检查必须覆盖应用持续运行、重新激活与系统唤醒的情况；每次启动不能变成周期轮询请求。
- 检查只读取候选版本与本地安装状态，发现更新立即显示“有新 DSH 版本”。不得因发现更新而自动下载安装。
- 设置界面的状态说明询问是否下载，并提供链接样式的“下载”按钮，不使用弹窗。用户点击后下载所提示的精确版本，失败后可手动重试。
- 待下载状态跨应用重启保留。首次启动所需运行时的安装与用户主动重新下载流程继续使用现有启动行为。
- 下载校验与启动健康检查分开；下载完成不得替换正在运行的服务或更新 `runtimes/current`。
- 启动健康检查通过后，按来源标签分别保留受管版本：`latest` 保留最新 3 个版本，其他每个标签各保留最新 2 个版本；多个标签共用的版本只保留一份。当前运行或用户固定的版本不在配额内时额外保留，不能自动删除。

## 后台任务提醒

- 仅在用户明确勾选后，将随应用提供的提醒插件加入 DSH web profile；禁用时移除。插件历史 API 门槛为 DSH `0.1.5-rc.3`，当前应用整体门槛 `0.1.6` 更高。
- 当前未签名发布方式不使用 macOS 系统通知接口。提醒由应用自身的短暂 AppKit 面板提供，无需系统通知授权；不保留待处理列表或历史。文档必须说明它不进入通知中心或锁屏，不受专注模式管理，且只在应用运行时可用。
- 应用在前台时不弹出提醒或播放完成音；后台会话需要用户处理或任务停止时可提醒。仅通过去重的后台 `completed` 事件播放一次 macOS 自带的 Crystal 提示音（macOS 11 起的系统设置名称，底层文件仍为 `Glass.aiff`）；待处理和其他结束原因不播放。设置中的测试提醒可试听同一完成音。提醒只包含通用文案与回到会话的标识，不包含会话正文、工作区路径或 API Key。
- DSH `0.1.6-alpha.2` 起使用 `sessionStatus`，此前从 `0.1.5-rc.3` 起使用 `pendingInteractions` 与列表状态。兼容分支需标明起始版本，便于上游迭代后清理。
