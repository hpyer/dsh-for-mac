# DshForMac 项目约束

通用产品与技术约束见 [AGENTS.md](../AGENTS.md)，具体流程见 [架构设计](architecture.md)。

## 子进程环境

- 子进程 PATH 优先使用选定 Node 与检测到的 pnpm 目录，保留继承路径，读取 `/etc/paths` 和 `/etc/paths.d`，再补齐两种 Mac 架构的 Homebrew 与系统目录，支持 DSH 内交互式 shell 查找配置依赖。仅影响子进程，不修改全局 PATH 或用户 shell 配置。
- 内嵌终端可使用本机已安装的 Nerd Font 补充私用区图标；兼容样式仅作用于终端，不自动安装字体、不修改 DSH 包。

## 菜单栏控制

- 菜单栏顶部显示 DshForMac 版本和 DSH 当前状态，操作区提供显示主窗口（⌘0）、重新加载页面（⌘R）、重启 DSH（⇧⌘R）和设置（⌘,）；其后集中放置 DSH 与应用更新检查，退出单独成组。关闭窗口不停止 DSH。
- 主窗口记住上次尺寸和位置；外接显示器变化后，不能让窗口停留在不可见区域。
- 唤醒后只探测已运行的本机 DSH 服务；确认断线后有限重试并在恢复后重载页面，失败时提供手动重连。不因探测自动下载或重启 DSH。

## DshForMac 应用更新

- 应用包标识为 `cn.hpyer.dshformac`；首次启动时从旧包标识的偏好设置域迁移用户设置，不清除旧域。
- 应用版本更新与 DSH 运行时更新互不依赖；即使 Node.js 或 DSH 不可用，也能检查 DshForMac 更新。
- 仅发布同时包含 x86_64 与 arm64 的单个通用 DMG，继续支持 macOS 11。更新包和更新源使用 Sparkle EdDSA 签名；不要求 Apple Developer ID 签名或公证。
- 默认每天检查应用更新，不静默下载或安装。发现新版后由用户选择稍后提醒、忽略此版本或立即升级；立即升级应安装并重启应用。
- 设置中的应用版本号旁与菜单栏均提供手动检查入口。检查、下载或安装失败时显示原因，并提供重试及 GitHub Releases 手动安装入口；签名校验失败不得绕过校验自动安装。
- 应用更新源是 GitHub Release 中的固定 `releases/latest/download/appcast.xml` 地址，不使用 GitHub Releases API。发布工作流缺少 Sparkle 私钥时不得发布不受验证的更新。
- 源码运行、只读 DMG 或应用转置环境不执行应用内替换；引导用户从发布页面手动安装。现有未包含更新器的旧版本需要手动升级一次。

## DSH 更新

- 设置中的“DSH 检查标签”支持多选，首项 `latest` 默认勾选且不可取消；检查标签与包下载镜像修改后立即保存，后续检查和下载直接使用新设置，无需先点击“保存”。
- 检查频率支持每次启动、每天、每周、每月和不检查。周期检查必须覆盖应用持续运行、重新激活与系统唤醒的情况；每次启动不能变成周期轮询请求。
- 检查只读取候选版本与本地安装状态，发现更新立即显示“有新 DSH 版本”。不得因发现更新而自动下载安装。
- 设置界面的状态说明询问是否下载，并提供链接样式的“下载”按钮，不使用弹窗。用户点击后下载所提示的精确版本，失败后可手动重试。
- 待下载状态跨应用重启保留。首次启动所需运行时的安装与用户主动重新下载流程继续使用现有启动行为。
- 下载校验与启动健康检查分开；下载完成不得替换正在运行的服务或更新 `runtimes/current`。
- 启动健康检查通过后，默认保留最新 5 个受管版本，稳定版与预发布版合并计数；当前运行或用户固定的版本不在其中时额外保留，不能自动删除。
