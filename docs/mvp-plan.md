# DshForMac MVP 验收计划

范围与边界见 [项目约束](project-constraints.md) 与 [架构设计](architecture.md)。

## 菜单栏快捷入口

- 关闭或最小化主窗口后，通过菜单栏“显示主窗口”可将原窗口置前；运行中的 DSH 不因关闭窗口而停止。
- 菜单栏顶部显示应用版本与随 DSH 启动、运行、失败和退出而更新的状态，文字清晰可读；第二组操作有显示主窗口（⌘0）、页面重载（⌘R）、重启（⇧⌘R）和应用设置（⇧⌘,），⌘, 留给 DSH；第三组是 DSH 与应用更新检查；退出单独成组。
- 调整窗口大小和位置后重新启动应用应恢复该布局；拔掉外接显示器后重新启动，窗口应回到当前可见屏幕。
- 睡眠唤醒后，健康的本机连接保持页面不变；断线后自动重试，恢复时重载页面。WebView 内容进程退出时触发同一恢复流程；重试耗尽后提供手动重连。
- DSH 0.2.0-rc.2 主对话应填满中间栏，消息区不塌缩，输入框保持在底部；切换会话、改变窗口大小和打开右侧面板后仍正常。WebKit 回归测试覆盖插槽包装及根节点高度塌缩后的恢复；旧版 macOS 仍需人工复验。
- 先用 DSH 0.2.1-alpha.1 或更新版本打开会话，再回退到 0.1.7-rc.2／0.2.0-rc.1／rc.2：会话内容继续加载，不因结构化草稿使会话插槽崩溃；输入框位于底部。切回新版时草稿和未编辑引用仍在；旧版编辑草稿后文字正常保存，未触碰引用保持正确偏移，清空草稿后引用同步移除。自动测试覆盖读写、未知字段、非目标存储、重复安装、存储异常与版本切换；2026-10-10 已通过 Xcode/LLDB 在 macOS 26.6.2 实际运行上述五个版本复验加载及布局，未发送消息。旧 macOS 与实际草稿编辑仍须人工复验。

## DSH 文件界面与 Market 重启

- 点击文件树、对话文件链接或产出物时，使用 DSH 内置预览；不出现第二个原生预览栏。新窗口请求中的本机链接在主 WebView 加载，外部链接和 `file:` 导航经确认后交给系统默认应用。
- 在 DSH 内置界面验证文本、Markdown、图片与 PDF 预览，重点人工复验 macOS 11 与 macOS 13。自动测试模拟缺失 API，验证页面及 PDF Worker 的兼容实现、原生实现保留，以及普通 Blob 不注入；会话测试验证 deferred Promise 的完成、拒绝与子类行为。移除原生预览不移除这些兼容测试。
- 文档字节读取回归：真实 WKWebView 强制触发 PDF Worker 兼容，检查原生 File、Blob.slice、Response.blob 与继承语义；multipart 响应覆盖 Word/PPT 单字节前置检查、Excel、PDF、图片、HTML、CSV/TSV 及空附件，验证 DSH 的 Blob 类型校验和字节保真。2026-10-16 完整 `swift test` 通过 58 项；这些是读取层测试，不等同于所有格式的完整渲染或旧系统实测，仍需实际文档复验。
- API 回归测试还覆盖数组不变性和空槽、循环克隆和共享缓冲区视图、大字体 Base64、真实 WebView 的 buffer 转移与失败保留、ReadableStream 完成/错误/取消后的锁释放、Response 消费语义及真实 Worker 字体转移。审计 DSH `0.2.0-rc.2` 和 `0.2.1-alpha.2`；旧系统人工验收补充模型排序、定时任务、轨迹及设置保存，不将缺失 API 模拟等同于完整旧系统实测，详见 [WebKit 兼容审计](webkit-compatibility.md)。
- DSH Market 发起重启时由原生运行时管理器重启受管进程。WebKit 回归测试验证仅拦截同源 POST 重启，GET、不同端口以及新旧文件打开 RPC 原样交给 DSH，后安装的 transport 不重复发送重启消息。

## 内嵌终端环境

- 从 Finder 启动，Node 位于版本管理器目录、fnm/direnv/starship 位于 Homebrew 目录时，打开 DSH 右侧 zsh 终端应正常加载个性化配置，不出现这些工具的 `command not found`。
- PATH 回归测试覆盖空路径、Finder 精简路径、继承自定义路径、去重和选定 Node/pnpm 优先级，位于 `Tests/DshForMacTests/SemanticVersionTests.swift`。
- 系统 PATH 测试覆盖 `/etc/paths`、按文件名排序的 `paths.d`、缺失文件和无效条目；已继承路径和选定 Node/pnpm 优先级不被系统条目覆盖。
- 安装 MesloLGS NF 后，内嵌终端应显示提示符的 Nerd Font 图标与 Powerline 分隔符；WebKit 测试验证字体可加载、普通字符宽度不变且不影响终端以外的文本。实际 DSH 界面仍需随版本升级人工复验。

## DSH 更新检查与下载

- 用 `0.1.5`、`0.1.6-alpha.2`、`0.1.6-rc.1`、恰好 `0.1.6` 和更高版本分别验证启动门槛；低版本保留在本地，显示所需最低版本与“检查 DSH 更新”入口，不进入 DSH 启动流程，也不能下载或作为回退目标。验证已选版本与 `current` 指向低版本两种情况，拒绝时保留目录、软链接及用户选择。
- 在 DSH `0.1.6` 及当前版本分别人工验证历史会话打开、创建会话、发送与重载；只使用隔离的测试数据，不用新版会话文件直接验证旧版回退。最低版本门槛不代表任意版本间的会话格式兼容保证。
- 设置中低于门槛的已安装版本不可再次选择，启动时会提示所需最低 DSH 版本；本地无兼容版本时，用户可检查并下载兼容版本。
- 设置中的“DSH 检查标签”支持多选，首项 `latest` 默认勾选且不可取消；检查标签与包下载镜像修改后立即保存，后续检查和下载直接使用新设置，无需先点击“保存”。
- 设置页将 DSH 检查按钮和结果放在“运行状态”栏，提供单独的“关闭”按钮；普通保存不关闭窗口，确认立即重启 DSH 时才关闭。只把当前运行版本写为明确选择时，不应误判为需要重启。
- 应用保持运行超过配置间隔，触发一次更新检查；尚未到期时，激活、重新打开窗口或唤醒不会重复检查。
- “每次启动”仅触发启动检查；“不检查”不自动检查；手动“检查 DSH 更新”不受上述频率限制。
- 检查失败保留最后成功检查时间，自动重试至少间隔 15 分钟。
- 检查发现 DSH 新版本立即显示“有新 DSH 版本”工具栏提示，设置显示询问下载的说明及“下载”链接；检查本身不创建安装清单、不清理未完成安装、不执行包管理器安装。
- 点击下载后按精确版本安装和校验，禁用重复下载与检查；失败后可以点击重试，完成后可从版本列表选择。
- 关闭并重新打开应用后保留待下载状态；下载不更改当前运行时指针。
- 启动健康检查通过后，按 SemVer 优先级保留最新 5 个受管版本（含预发布版）；更旧的当前运行版本或用户固定版本仍受保护，不因数量上限被删除。

自动回归测试位于 `Tests/DshForMacTests/DSHUpdateTests.swift`，使用独立临时目录、独立设置和本地 npm 测试替身，不访问真实 registry。

## 会话降级兼容修复与恢复

- 仅在历史加载出现未知必需事件错误时显示“修复会话格式…”按钮；普通消息里相同文字、网络错误、子框架和非本机页面不能触发操作，不自动修改会话。
- 在隔离 V4 会话中加入 `job/registered`、`job/settled`，分别选择 DSH `0.2.0-rc.2`、`0.2.1-alpha.1` 和 `0.2.1-alpha.2`：修复前确认会重启 DSH及无法恢复新版任务状态。取消时没有备份或日志写入。确认后先持久备份并校验原压缩字节，修复通过目标严格读取校验后再替换，重新打开会话可读取原消息；新版读取器仍保留所有事件内容。
- 损坏的压缩帧、截断尾部、序号断裂、其他必需未知事件、不同格式代际、缺少严格读取器/会话锁和目标读取器拒绝的载荷都停止修复；不删除事件，不更改序号，不接受数据目录外路径或符号链接。
- 验证备份失败时原日志不变；修复和恢复均拒绝覆盖检查后新增的历史；其他 DSH 进程持有 `session.lock` 时拒绝操作，锁文件不删除。恢复校验备份摘要，先备份修复后的分支，再逐字节恢复原始日志。验证“文件 → 恢复会话备份…”可找到备份；原始日志若需要新版读取，界面须说明。
- `swift test` 覆盖桥接按钮、请求验证与原有回归。`node --test scripts/tests/session-repair.test.mjs` 覆盖压缩帧和路径拒绝；设置 `DSH_REPAIR_TEST_RUNTIME` 为受管 `0.2.0-rc.2` 目录可运行真实读取器、排他锁、备份、失败与恢复回归，另设 `DSH_REPAIR_TEST_NEWER_RUNTIME` 为受管 `0.2.1-alpha.4` 目录可验证新版仍能读取。设置 `DSH_REPAIR_TEST_VERSIONS_ROOT` 为受管版本父目录，逐一运行已安装版本的读取、修复与恢复；`0.2.1-alpha.3`、`alpha.4` 已认识任务事件，应提示无需修复，不生成备份或改写日志。当前实际读取器回归覆盖 `0.2.0-rc.2`、`0.2.1-alpha.1`、`alpha.2`、`alpha.3` 和 `alpha.4`；更早版本按实际能力检测，不宣称已完成实测。只操作临时测试会话，不触碰用户会话；实际错误页面及 macOS 11/双架构仍需人工复验。

## DshForMac 应用更新

- 每个发布版本的更新日志条目包含与应用常量一致的“最低兼容 DSH 版本”行；GitHub Release Notes 包含同一行，缺失或不一致时发布工作流失败。
- 发布包的 `CFBundleIdentifier` 为 `cn.hpyer.dshformac`；首次启动迁移旧包标识下的设置，且不覆盖新域已有的值。
- 在 Intel 和 Apple Silicon 上分别完成构建与测试，发布的唯一 DMG 包含两种架构，最低系统版本仍为 macOS 11。
- 发布包的 Sparkle 框架、运行路径、EdDSA 包签名和更新源签名均通过验证；缺少发布密钥时不能公开 Release。
- 设置版本号旁、应用菜单和系统菜单栏的“检查 DshForMac 更新”都能触发手动检查；与“检查 DSH 更新”独立。
- 发现新版后可稍后提醒、忽略此版本、安装并重启；手动检查仍能找到已忽略版本。
- 在网络故障、只读 DMG、应用转置或安装失败时保留旧应用，提示原因并提供 GitHub Releases 手动安装入口；签名失败不能自动安装。
- 使用旧版应用的用户手动安装一次新版本后，验证下一次应用内升级。分别在 macOS 11、Intel 和 Apple Silicon 上做真实应用升级测试。

## 后台任务提醒

- 当前应用支持的 DSH 版本均满足提醒插件的历史 API 门槛 `0.1.5-rc.3`；插件最低版本单元测试保留，用于记录 API 起始版本，不代表应用支持运行旧 DSH。
- 分别以 DSH `0.1.6` 和当前版本验证待审批、待回答、待审阅和任务结束事件；初次加载、页面重连、重复状态和主窗口置前时不重复提醒。
- 对有 `turn/end` 的已完成、取消与失败分别检查文案：只有 `completed` 显示“已完成”；未保留会话的停止使用“已结束”。
- 后台事件显示不激活应用的短暂面板；点击“打开会话”显示主窗口并定位会话。面板约 8 秒后消失，不保留待处理列表或历史。后台任务成功完成时，卡片伴随一次系统 Crystal 完成音（底层 `Glass.aiff`）；前台、重复、无效、待处理和其他结束原因不播放。设置中勾选后台任务提醒后可发送测试提醒，验证前台卡片并试听完成音而不调用 DSH 会话。原生回归使用替身播放器验证触发次数，测试不实际播放声音；当前系统核对 Apple 的 `AlertSounds.loctable` 中 `Glass → Crystal` 映射，并验证系统文件可被 `NSSound` 加载。Crystal 在 macOS 11 Big Sur 已提供，覆盖应用最低版本；这是资料与当前系统验证，不代表所有旧版本已完成真机测试。macOS 11/13 上的实际声音、系统音量及静音下的音频输出仍需人工验证。关闭主窗口后应用继续运行并能显示提醒；应用退出或 Mac 睡眠时不显示。
- 验证 macOS 11、Intel 与 Apple Silicon 上的面板展示、全屏和多桌面空间行为。界面及说明文档应明确：这是应用内提醒，无需系统通知授权，不进入通知中心或锁屏，不受专注模式管理。当前未签名发布方式不使用系统通知接口。
