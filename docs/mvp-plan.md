# DshForMac MVP 验收计划

范围与边界见 [项目约束](project-constraints.md) 与 [架构设计](architecture.md)。

## 菜单栏快捷入口

- 关闭或最小化主窗口后，通过菜单栏“显示主窗口”可将原窗口置前；运行中的 DSH 不因关闭窗口而停止。
- 菜单栏顶部显示应用版本与随 DSH 启动、运行、失败和退出而更新的状态，文字清晰可读；第二组操作有显示主窗口（⌘0）、页面重载（⌘R）、重启（⇧⌘R）和应用设置（⇧⌘,），⌘, 留给 DSH；第三组是 DSH 与应用更新检查；退出单独成组。
- 调整窗口大小和位置后重新启动应用应恢复该布局；拔掉外接显示器后重新启动，窗口应回到当前可见屏幕。
- 睡眠唤醒后，健康的本机连接保持页面不变；断线后自动重试，恢复时重载页面。WebView 内容进程退出时触发同一恢复流程；重试耗尽后提供手动重连。

## 内嵌终端环境

- 从 Finder 启动，Node 位于版本管理器目录、fnm/direnv/starship 位于 Homebrew 目录时，打开 DSH 右侧 zsh 终端应正常加载个性化配置，不出现这些工具的 `command not found`。
- PATH 回归测试覆盖空路径、Finder 精简路径、继承自定义路径、去重和选定 Node/pnpm 优先级，位于 `Tests/DshForMacTests/SemanticVersionTests.swift`。
- 系统 PATH 测试覆盖 `/etc/paths`、按文件名排序的 `paths.d`、缺失文件和无效条目；已继承路径和选定 Node/pnpm 优先级不被系统条目覆盖。
- 安装 MesloLGS NF 后，内嵌终端应显示提示符的 Nerd Font 图标与 Powerline 分隔符；WebKit 测试验证字体可加载、普通字符宽度不变且不影响终端以外的文本。实际 DSH 界面仍需随版本升级人工复验。

## DSH 更新检查与下载

- 用低于 `0.1.5-rc.1`、恰好 `0.1.5-rc.1` 和更高版本分别验证启动门槛；低版本保留在本地，显示所需最低版本与“检查 DSH 更新”入口，不进入 DSH 启动流程，也不能作为回退目标。
- 设置中低于门槛的已安装版本不可再次选择，启动时会提示所需最低 DSH 版本；本地无兼容版本时，用户可检查并下载兼容版本。
- 设置中的“DSH 检查标签”支持多选，首项 `latest` 默认勾选且不可取消；检查标签与包下载镜像修改后立即保存，后续检查和下载直接使用新设置，无需先点击“保存”。
- 设置页将 DSH 检查按钮和结果放在“运行状态”栏，提供单独的“关闭”按钮；普通保存不关闭窗口，确认立即重启 DSH 时才关闭。只把当前运行版本写为明确选择时，不应误判为需要重启。
- 应用保持运行超过配置间隔，触发一次更新检查；尚未到期时，激活、重新打开窗口或唤醒不会重复检查。
- “每次启动”仅触发启动检查；“不检查”不自动检查；手动“检查 DSH 更新”不受上述频率限制。
- 检查失败保留最后成功检查时间，自动重试至少间隔 15 分钟。
- 检查发现 DSH 新版本立即显示“有新 DSH 版本”工具栏提示，设置显示询问下载的说明及“下载”链接；检查本身不创建安装清单、不清理未完成安装、不执行包管理器安装。
- 点击下载后按精确版本安装和校验，禁用重复下载与检查；失败后可以点击重试，完成后可从版本列表选择。
- 关闭并重新打开应用后保留待下载状态；下载不更改当前运行时指针。
- 启动健康检查通过后，按 SemVer 优先级保留最新 5 个受管版本（含预发布版）；更旧的当前运行版本或用户固定版本仍受保护，不因数量上限被删除。

自动回归测试位于 `Tests/DshForMacTests/DSHUpdateTests.swift`，使用独立临时目录、独立设置和本地 npm 测试替身，不访问真实 registry。

## DshForMac 应用更新

- 每个发布版本的更新日志条目包含与应用常量一致的“最低兼容 DSH 版本”行；GitHub Release Notes 包含同一行，缺失或不一致时发布工作流失败。
- 发布包的 `CFBundleIdentifier` 为 `cn.hpyer.dshformac`；首次启动迁移旧包标识下的设置，且不覆盖新域已有的值。
- 在 Intel 和 Apple Silicon 上分别完成构建与测试，发布的唯一 DMG 包含两种架构，最低系统版本仍为 macOS 11。
- 发布包的 Sparkle 框架、运行路径、EdDSA 包签名和更新源签名均通过验证；缺少发布密钥时不能公开 Release。
- 设置版本号旁、应用菜单和系统菜单栏的“检查 DshForMac 更新”都能触发手动检查；与“检查 DSH 更新”独立。
- 发现新版后可稍后提醒、忽略此版本、安装并重启；手动检查仍能找到已忽略版本。
- 在网络故障、只读 DMG、应用转置或安装失败时保留旧应用，提示原因并提供 GitHub Releases 手动安装入口；签名失败不能自动安装。
- 使用旧版应用的用户手动安装一次新版本后，验证下一次应用内升级。分别在 macOS 11、Intel 和 Apple Silicon 上做真实应用升级测试。

## 后台任务提醒

- DSH `0.1.5-rc.1` 与 `0.1.5-rc.2` 可继续使用应用，但保存设置时不得启用提醒插件；正式版 `0.1.5` 和更高版本满足插件版本门槛。
- 分别以 DSH `0.1.5-rc.3` 和 `0.1.7-rc.1` 验证待审批、待回答、待审阅和任务结束事件；初次加载、页面重连、重复状态和主窗口置前时不重复提醒。
- 对有 `turn/end` 的已完成、取消与失败分别检查文案：只有 `completed` 显示“已完成”；未保留会话的停止使用“已结束”。
- 后台事件显示不激活应用的短暂面板；点击“打开会话”显示主窗口并定位会话。面板约 8 秒后消失，不保留待处理列表或历史。设置中勾选后台任务提醒后可发送测试提醒，验证前台卡片而不调用 DSH 会话。关闭主窗口后应用继续运行并能显示提醒；应用退出或 Mac 睡眠时不显示。
- 验证 macOS 11、Intel 与 Apple Silicon 上的面板展示、全屏和多桌面空间行为。界面及说明文档应明确：这是应用内提醒，无需系统通知授权，不进入通知中心或锁屏，不受专注模式管理。当前未签名发布方式不使用系统通知接口。
